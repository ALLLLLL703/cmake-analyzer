# Project Architecture

## Current implementation

The `master` branch contains the handwritten CMake analysis pipeline and an analyzer-backed LSP executable. `src/main.rs` starts the clap CLI; `src/lib.rs` exports model, parser, workspace, runtime_cmake, server, config, cli, and the pure semantic formatter under format. The old `rpc` scaffold has been removed. The `lexer`, `nparser`, `semanticer`, `build-struct`, and `dependency-graph` inspection binaries are under `cli/parser/`.

## Cargo workspace

- Root `Cargo.toml`: the analyzer package and `crates/lspally` library share a Cargo workspace with resolver 3. Existing `clap`, `owo-colors`, and `tokio` versions/features live in `[workspace.dependencies]`; both packages inherit them. `lspally` also inherits `serde` (derive), `serde_json`, and `lsp-types 0.97`.
- `crates/lspally/Cargo.toml` and `src/lib.rs`: edition 2024 library exporting `rpc` and `server`. `server/model.rs` declares the server framework; `server/wrapper/` implements stream transport and execution. The root analyzer package depends on lspally; fluent-uri reuses its existing URI parser/percent decoder for local file paths.

## LSP JSON-RPC

- `crates/lspally/src/rpc/model.rs`: serde-compatible `Request`, `Notification`, `Response`, and untagged `Message`; JSON-RPC version is always 2.0. IDs reuse `lsp_types::NumberOrString`; parameters reuse its object/array union. Unknown method names and raw parameters remain available; there is no duplicate method enum or registry. Absent/null parameters normalize to omission. Responses contain either a JSON result (including null) or an error; null IDs are only accepted for errors.
- `rpc/methods.rs`: generic construction and parameter extraction use `lsp_types::request::Request` / `notification::Notification` markers and associated types. `take_params` consumes the JSON tree without cloning and retains the envelope/ID. `decode_response` verifies method and ID before consuming and decoding the result into the request's associated result type. Outstanding-request tracking is left to the caller. Raw progress parameters preserve partial results not modeled by lsp-types' work-done progress type.
- `rpc/serde.rs`: small adapters preserve missing-vs-null result/error fields, reject notifications carrying IDs and responses with both/neither payloads, and classify messages by field presence without falling back from malformed requests to notifications.
- `rpc/display.rs`: `to_lsp_string(&message)` and `.display()` return a fallible String containing `Content-Length: <UTF-8 bytes>\r\n\r\n<compact JSON>`. No ANSI colors or extra trailing newline. Serialization errors are returned; no framing parser or stream I/O is implemented.

## Reusable LSP server

- `server/model.rs`: `ILanguageServer` requires 51 standard request handlers, 20 notification handlers, and two custom hooks, without default bodies. `Wrapper<S>`, `ClientHandle`, `Limits`, and private session state live here. The direction inventory is in `todos/d1/lsp-methods.md`.
- `server/model/`: independent document, lifecycle, capabilities, edits, diagnostics, and feature records. Standard business APIs expose neither serde nor lsp-types. `Data` carries arbitrary application data; only `Extension` exposes raw JSON. `Position` uses zero-based coordinates in `Context::encoding`; the wrapper does not translate analyzer byte spans or manage document text.
- `model/context.rs`: business errors, negotiated UTF-8/UTF-16/UTF-32 encoding, and cooperative cancellation. `model/client.rs`: URI/version-qualified diagnostic publications and arbitrary partial-result progress.
- `wrapper/convert/`: moved field-level model adapters; private lsp-types scalar wrappers use small serde bridges. `dispatch.rs` routes standard methods into feature handlers under `handlers/`; only unknown non-reserved methods reach extension hooks. Known invalid parameters return InvalidParams, not an extension fallback.
- `wrapper/runtime.rs`: `Wrapper::run(reader, writer)` and `run_stdio`. One business worker preserves notification/query arrival order; an independent reader receives responses while a handler awaits a client call. Queues and outstanding client requests are bounded. Full request queues produce errors; full notification queues end the connection rather than silently losing document changes.
- `wrapper/lifecycle.rs`: client capability checks, dynamic-registration method checks, initialization progress token, and position encoding negotiation. The reader enforces initialization/shutdown phases and applies cancellation/trace actions before business hooks. Successful shutdown retires outgoing waits; exit/EOF cancels the session and joins tasks, including a failed worker or blocked writer.
- `wrapper/transport.rs`: bounded ASCII CRLF headers, one Content-Length, UTF-8 bodies, exact reads, and one serialized writer with flush acknowledgements. Reader-generated errors enqueue without awaiting a socket flush. Logs use stderr, not protocol stdout.
- `wrapper/client.rs` and `pending.rs`: typed standard outgoing calls, unique IDs, response correlation, capability/lifecycle checks, initialization-output restrictions, diagnostics clearing, work-done/partial progress, and trace filtering. Short pending-map locks are never held across a business await; drop guards retire abandoned waits.
- `scripts/gen/lspally-schema/`: authored generators for seed models/adapters, method inventory, registration checks, and explicit unsupported test scaffolding. Seed output is not a complete regeneration of manually adapted production files. Generated sections retain script-origin labels; manual changes are marked separately. Temporary verification sources stay outside `target/`. User-approved persistent tests now live in package-root `tests/` directories.
- Current execution is serialized, not parallel query execution. Business implementations choose advertised feature capabilities and own text/version semantics. No HTTP or reconnect is implemented; execution policy belongs to the analyzer, not this wrapper. The analyzer integration is in `src/server/`, separate from this reusable crate.

## Semantic data

Semantic arena models are defined in `src/parser/semanticer/model.rs`; `reference_model.rs` defines and reexports reference/function/warning records. See [References](../src/parser/semanticer/REFERENCES.md).

- `Semanticer`: parsed input, active and injected schema maps, and selected CMake version.
- `SemanticedBuffer`: commands, variables, functions/macros, sparse command-qualified possible values, diagnostics, warnings, unresolved references, blocks, scopes, and root symbols.
- `SemanticCommandRepresent`: command/name ranges, original argument forms, closure state, block/scope IDs, an optional shared `Arc<CommandSchema>`, named argument references extracted before binding, cached schema path-role argument positions, and optional shared leading-comment documentation.
- `SemanticBlock`: kind, direct command IDs including its own opening/closing commands, child block IDs, parent ID, closure state, and full range. Descendant commands are not duplicated in ancestor membership lists.
- `SemanticScope`: independent scope record associated with a block by `BlockId`, with an optional parent `ScopeId`.
- `SemanticVariable`: name, reference-qualified values instead of initial/final value fields, optional scope ID, and optional `first_write` range for the earliest possible source write. `VariableChanging` stores command ID, raw Out-argument span, and optional set documentation; distinct output arguments in one command retain distinct locations. Spans belong to the owning SemanticedBuffer file/snapshot and include quote/bracket delimiters. Unwritten builtin/specialized descriptors have no source location. These are possible writes, not proven runtime initialization. Global scopes use `None`; scoped variables are distinguished by `(scope, name)`.
- `ReferenceLocation`: Workspace-local FileId, snapshot-local CommandId, name span, definition/read/write/call role, and optional position-qualified PossibleValue. Variables retain local references; SemanticFunction stores Builtin/Function/Macro kind, optional source definition/body block, parameter locations, definition/call references, and optional shared documentation. Used native commands have no definition/body/parameters; canonical names aggregate calls without entering user-function bindings. Known user shadows remain separate. Unused builtin commands are not materialized. Unresolved names retain locations without invented definitions. `SemanticWarn` carries possibly-unset/unset/empty variable warnings; literal state tracking does not evaluate CMake.
- `SemanticSymbol`: a range and an ID reference to a top-level block or command. It does not duplicate commands, blocks, or their children.

Command/block/scope IDs are indices into one analysis snapshot, not persistent identities across parses. Reference environments, graph visits, indexed symbols, and snapshot-local symbol slots use distinct ID structs with explicit index accessors; numeric clocks, argument positions, and byte offsets remain numeric values.

## Analysis pipeline

`Semanticer::parse(source, file_id).await` in `src/parser/semanticer/parsing.rs` assembles these stages:

1. `scan_version` in `parsing/version.rs`: select the minimum declared by `cmake_minimum_required(VERSION ...)`; otherwise asynchronously run `cmake --version`. Version ranges select their lower bound.
2. Load versioned schemas and builtin variable records, then overlay constructor-injected schemas.
3. `scan_commands`: convert nparser commands to semantic records and diagnose syntax errors and commands absent from the schema map. documentation.rs binds immediately preceding standalone comment groups to function/macro/set commands; blank lines or intervening code break attachment.
4. `scan_blocks` in `parsing/block.rs`: recognize `if`, `while`, `foreach`, `function`, `macro`, and `block` pairs using builtin keyword commands. Diagnose missing or unexpected ends, invalid branch placement, repeated `else`, and `elseif` after `else`. An ancestor end can recover past unfinished inner blocks; those inner blocks remain unclosed and receive diagnostics.
5. `scan_scopes` in `parsing/scope.rs`: establish function scopes and statically identified variable scopes from `block()`. Plain `block()` creates a variable scope; `SCOPE_FOR POLICIES` alone does not. Macro and control-flow blocks inherit their surrounding variable scope. Opening declarations belong to the surrounding scope; their bodies belong to the newly established scope.
6. `scan_functions` in `parsing/functions.rs`: collect function/macro declarations and formal parameters after blocks/scopes.
7. `detect_specialized_variables` in `parsing/templates.rs`: generate concrete builtin descriptors from literal triggers, remove unresolved templates from the result, and merge names without duplicates. The public method returns `Vec<SemanticVariable>` and remains usable after parsing.
8. `track_variable_changes` in `parsing/outputs.rs`: traverse semantic commands only, locate schema `Out` arguments, and record first/per-argument write spans in the owning scope. Incremental updates rebuild these locations from remapped arguments, including reused commands. It does not revisit nparser nodes or source text.
9. `collect_references` in `references.rs`: bind argument references, declarations, used-native/user calls, and literal variable-state warnings. local_index shares file-only collector replay with navigation; private flow models live in `references/model.rs`. Static reads are extracted earlier by `parsing/references.rs`; schema Variable arguments share the structural matcher with Out arguments.
10. `collect_values` in `values.rs`: sparse literal/simple-expansion observations, conservative invalidation, and reference-value annotation; value_model.rs holds provenance-tagged values, bindings, and directory context. Unknown/deferred/nonlocal values remain absent. values/arguments.rs shares position-qualified simple argument expansion between completion and target binding; conflicts across visits remain unknown and expansions do not create new target names.
11. `collect_symbols` in `parsing/symbols.rs`: assemble root block/command references in source order. Nested members remain accessible through the block arena.

## Schema and output matching

- `src/parser/semanticer/schema.rs`: scalar argument roles, explicit InputFile/InputDirectory/InputPath/ModulePath/OutputPath filesystem roles (generic Path remains unspecified), and Keyword/Optional/Repeat/Choice/AllOf grammar nodes. Grammar groups expose structured multi-token expressions while preserving a single snippet placeholder; CacheEntry recognizes CACHE{name} dispatch and avoids ordinary output writes. NameRole identifies variable, LanguageType, and generic/executable/library/custom-target name slots. ArgSchemaKind::LanguageType marks project LANGUAGES/legacy language lists, enable_language, and compile/link language operands. schema/languages.rs records the 16 builtin language names and introduction versions, including ASM_POASM in 4.4.
- `schema/builtin.rs`: native command registration/version layers plus final structured keyword overrides; schema_layers borrows effective trees, while schemas_for_version materializes the same order for analysis. builtin/keyword_schemas.rs caches only requested versions in 37 supported OnceLock slots and filters overrides against native registration. all_transform.rs, all_build.rs, all_process.rs, and all_lookup/ partition all previously incomplete grammars; project.rs and find_package.rs model project metadata and package modes. All 132 registered 4.4 command names match the official catalogue; no effective builtin retains Unmodeled/Action/Unknown tails. Scalar validation, duplicate-option semantics, runtime/policy constraints, and experimental gate activation remain outside this grammar metadata. See schema/README.md.
- `variables/builtin.rs`: lazy static `SemanticVariable` tables; `variables_for_version` applies variable additions. Unwritten reference values remain unknown. The raw catalogue retains templates; `template_names_for_version` exposes their versioned names without cloning variable records.
- `parsing/templates.rs`: specialize all nine placeholder families using project/language/package/config/linker/policy triggers, literal feature names, regex capture descriptors, known local function-call arities, and explicit concrete variable names. Combined templates need every placeholder resolved. These are descriptors, not proof of runtime initialization. Template triggers do not use evaluated values or cross-file call arities.
- `parsing/outputs.rs`: sequence/group/step share structural schema matching. Full-call output/path/reference binding keeps literal preference and intersection across equal matches. Keyword completion separately computes exact completed-prefix specificity and rejects weaker per-word interpretations; active proposed words add no specificity. CacheEntry tokens rank namespace dispatch; structured Grammar nodes share normal group matching. The crate-visible completion_roles prefix mode preserves unfinished suffixes and unions supported active-slot alternatives, recording only that slot to avoid copying growing repeat histories. target_link_libraries now models visibility/config selectors and repeated target/link slots. Unresolved output names or earlier unquoted expansion/list splitting still prevent a guessed write. target_arguments uses full-call binding intersection; outputs/trails.rs shares target match histories in an arena to avoid copying growing repeat prefixes or recursive list destruction. TargetTrailId is local to that arena.

## Incremental computation

See [Incremental analysis](../src/parser/INCREMENTAL.md) for the reading order, example, and invalidation rules.

- `src/model/incremental.rs`: UTF-8-safe replacement envelopes, unchanged range mapping, line/sparse Unicode position indexes, and work counters.
- `lexer/incremental.rs`: whole-unit checkpoints retain parenthesis state; `parse_until` shares the full scanner. Relex from before the edit until unchanged suffix/state alignment, or EOF. Tokens, diagnostics, comment ranges, and checkpoint comment counts retain full-analysis behavior.
- `nparser/incremental.rs`: reuse complete closed-command units; reparse changed/error units through the same `parse_next` implementation. Lexer diagnostics and comment ranges are inherited anew. Cache state is declared in each layer's `model.rs`.
- `semanticer/incremental.rs`: reuse unchanged command payloads/schema Arcs and cached Out matches. Rebuild block/scope links when dense IDs/keyword structure change, and specialized variables when template inputs change. Leading comment groups rebind from current parser ranges even for reused command payloads. Version declaration changes invalidate all schema-dependent results. Builtin-only incremental caches pin a host-detected version until reconstruction.
- `build_struct/incremental.rs`: cache per-command effect/diagnostic ranges; regenerate selected commands and refresh source references of reused facts. Target metadata is reused without stale reference lists; bind_local rebuilds target references against current commands/ranges, including reused declarations. Schema identity prevents reuse across catalog changes.
- `workspace/references.rs`: aggregate variables/functions/unresolved references and contextual warnings in command/dependency order into shared immutable Arc<ReferenceIndex> RootGraph.references. Includes and resolved package scripts share an environment; subdirectories fork it. Functions-only visits use ReferenceCollector::function_command, importing unconditional top-level function/macro declarations in dependency/source order without variable/body/value effects. `reference_values.rs` replays contextual values alongside references into RootGraph.values and indexed-variable summaries. Shared snapshots remain immutable. Index rebuilding runs on a bounded blocking worker after graph rebuild or snapshot refresh, including edits that reuse dependency visits.
- `workspace/incremental.rs`: connect per-file caches on the bounded parser worker. Snapshots share lexical/semantic/build Arcs instead of cloning whole outputs. IncrementalLexer.buffer is an immutable Arc<LexedBuffer>; updates replace it, retaining old snapshot tokens/comments/checkpoints. LexedBuffer::parenthesis_depth searches checkpoint state by byte boundary for completion context. `workspace/refresh.rs` retains clean dependency visits/scopes if graph inputs, scope layout, and fact positions are unchanged; otherwise the ordered dependency walk replays.
- Incremental caches expose work counters. Source comparison, output materialization, variable aggregation, local reference/warning binding, and position/ID updates may remain linear. Reference spans reuse cached commands, but inventories/binding and the Workspace reference index are rebuilt, not edit-size-only. Full parse/analyze APIs remain the reference and are still used by inspection CLIs.
- `tests/performance/references.rs`: ignored release benchmark for full lexer/nparser/semantic analysis and fresh/warm-edit Workspaces. [Recorded comparison](../tests/performance/REFERENCES.md) includes the reference-index replay regression; no machine-specific acceptance thresholds.
- Differential tests in `tests/unit/parser/incremental.rs` check all four layers against fresh full analysis and assert local reuse. Workspace tests check graph reuse, revision references, immutable old snapshots, and context invalidation.

## Semantic inspection CLI

- `src/parser/semanticer/display.rs`: borrowed, streaming `SemanticedBuffer::display(colored)` adapter. It prints version, root symbols, commands and raw argument forms, blocks, scopes, variables/write IDs, function/reference locations, warnings, and diagnostics without cloning the analysis arenas. Source-derived strings are debug-escaped; Color formatting uses the existing `owo-colors` dependency with a reusable `Style` palette; no handwritten ANSI escapes.
- `SemanticDisplay::with_all_variables`: opt into unchanged builtin variable records, which are hidden by default to avoid flooding the output.
- `cli/parser/semanticer/args.rs`: positional file or `-`/stdin, `--text`, `--color`, and `--all-variables`.
- `io.rs`: asynchronous input loading. `output.rs`: lexer/parser/semantic analysis and buffered display writing. `main.rs`: CLI assembly and a blocking worker for analysis/rendering; the worker uses the running Tokio handle for asynchronous version detection.
- Exit codes: `0` for clean analysis or broken pipe, `1` when analysis diagnostics exist, and `2` for input/output failures. Clap handles invalid CLI arguments. Color is explicit, disabled by default, and distinguishes headings, IDs, keyword/native/external commands, scopes, variables, outputs, argument forms, closure states, and errors.

## Build structure and Workspace

See [Workspace README](../src/workspace/README.md) for flow, examples, and limits.

- `src/parser/build_struct/model.rs`: temporary borrowed BuildStructAnalyzer, ordered facts, snapshot-qualified SourceRef, typed projects/targets/source sections/file sets, dependency requests, and possible writes. TargetDeclaration.references contains TargetReference (SourceRef, raw argument span, Definition/Read kind). Local BuildStruct lists contain file-local bindings; owner-qualified copies live in RootGraph.targets. Target source/argument arrays use shared immutable Arc slices to avoid copying large payloads per owner.
- `build_struct/target_references/`: collect.rs::TargetCollector gathers literal declarations and explicit schema target operands; resolve.rs binds unique visible names and typed target classes. Regular/GLOBAL imported targets are project-visible; nonglobal imports use CMake directory ancestry. Aliases keep separate definitions and inherit known original visibility; ambiguous names remain unbound. TargetDirectoryId and TargetEntryId belong to one collector. Unknown unquoted splitting/empty removal suppresses later argument binding; explicit external schemas retain their own roles, while native shadows do not inherit native roles. Declaration flags remain structural; dynamic flags, IMPORTED_GLOBAL promotion, and runtime invocation directories are not evaluated.
- `workspace/targets.rs`: reconstructs target directory ancestry from dependency visits, with include sharing and subdirectory nesting, then aggregates owner-qualified declarations without mutating snapshots. Functions-only external visits do not enter target collection. references.rs installs RootGraph.targets on the existing bounded analysis worker after variable/function aggregation, on graph rebuilds and snapshot-only refreshes.
- `build_struct/analyze.rs`: native-command dispatch and conditional/deferred ownership; injected schemas can supply Out writes but do not masquerade as native build commands. `project.rs`, `targets.rs`, and `sources.rs` extract supported literal structure and retain raw/unresolved arguments. dependencies.rs shares include/subdirectory/find_package request extraction with navigation; Dependency retains package arguments and Package kind.
- `build_struct/display.rs`: borrowed `BuildStruct::display(colored)` adapter; ordered facts, raw arguments, conditional/deferred/unresolved markers, and optional borrowed semantic diagnostics/warnings. `cli/parser/build_struct/{args,io,output,main}.rs` supplies file/stdin/text and explicit colors; it does not load dependencies.
- `workspace/display.rs`: `Workspace::display(colored)` returns `WorkspaceDisplay` with the requested public `DependcyGraphDisplay` field. The field's `DependencyGraphDisplay` adapter draws an ASCII visit tree with `owo-colors`, distinguishes include/package/subdirectory edges and missing/unresolved/unvisited candidates, and prints scopes and diagnostics. Iterative printing indexes edges once and retains repeated visits; source labels are escaped and repeated snapshot diagnostics are shown once. Pending/stale graphs are not displayed as current results.
- `cli/parser/dependency_graph/{args,io,output,main}.rs`: root file/stdin/text, explicit colors, binary directory, module search paths, and builtin directory; asynchronous input/Workspace flush followed by buffered rendering on a blocking worker. Stdin/text uses `cwd/CMakeLists.txt` for relative dependencies. Exit codes match semantic inspection: 0 clean/broken pipe, 1 diagnostics, 2 I/O errors. No configure is run.
- `src/workspace/model.rs`: documents/snapshots, one root and optional graph per Workspace, visits, directory contexts, variable scopes, graph edges, and limits. Multiple projects require separate Workspaces; root IDs and multi-root maps are removed. Graph facts reference retained immutable snapshots rather than copying declaration payloads. Scope write sets share copy-on-write state.
- `workspace/documents.rs`: normalized absolute file identities, overlays, root-bound construction/module-path settings, snapshots, and release of unused cached snapshots. set_script_working_directory supplies explicit script source/binary context and disables implicit project defaults regardless of filename; graph.rs/reference_values.rs preserve that context. Symlink aliases are not canonicalized.
- `workspace/parser.rs`: `flush` coalesces pending edits, incrementally updates known files in bounded blocking workers, checks revisions, and refreshes or rebuilds its one graph when project inputs change. `flush_documents` analyzes standalone overlays without traversal; `load_snapshot` supports one-file reads without inserting a dependency edge. A dependency-path set replaces the old reverse-root map. Unchanged semantic snapshots are reused. `flush` is currently serialized through `&mut Workspace`; it is not yet a concurrent LSP actor. Profiles retain standalone minimum-version selection; global catalogs/context generation and cached executable probing remain M3 work.
- `workspace/packages.rs`, `packages/{model,request,candidates}.rs`: static Find-module/config entrypoint resolution with MODULE/CONFIG/NO_MODULE, prefer-config, NAMES/CONFIGS, HINTS/PATHS/PATH_SUFFIXES, known package DIR/ROOT and CMAKE_PREFIX_PATH values/environment, and configured prefixes. Exact config directories are checked before shallow conventional prefix/lib/share/multiarch enumeration. This is source discovery, not version/component/architecture/toolchain/provider/registry/CPS evaluation; no CMake/project execution. Required unresolved requests warn, optional ones retain edges only. Module lookup enable also gates variable/environment package search.
- External import policy: graph entry canonical saved paths are compared with the root entry directory. Include and package policies are independent; add_subdirectory remains normal project analysis. None retains resolved navigation edges without loading. Functions loads direct/static dependency snapshots, propagates functions-only mode down that subtree, and exports only unconditional top-level function/macro declarations. No variable/value/target/body-reference effects escape; declaration order is retained. Full uses existing conservative traversal. Completion dependency sources exclude functions-only visits; workspace symbols render only their declarations unless explicitly opened/fully indexed elsewhere. Explicit external editor buffers remain locally analyzable. No FetchContent/ExternalProject checkout discovery.
- `workspace/graph.rs`: iterative source-order dependency traversal, dependency-path tracking, active-cycle/work limits, optional/missing module handling, and include/subdirectory scope differences. Include shares caller scope/source directory; subdirectories copy the caller-visible possible-write state. The crate-visible resolve_dependency_in/resolve_dependency_at helpers also serve navigation with identical module/package precedence; direct-path candidates can be missing, so navigation validates target existence separately. Local variable blocks get separate scopes. `graph/values.rs` advances literal value state in command order; simple known expansions can resolve dependency paths. Conditional/deferred dependencies remain candidate edges. Edits to any visited text force a graph rebuild when variable-dependent paths exist, rather than reusing potentially stale targets.
- Loose open files receive local analysis without root registration. Workspace accepts explicit static module search paths and a builtin module directory; the server supplies configured/default directories, including best-effort builtin discovery. Policy options are recorded, not interpreted. Scope state records project names, possible writes, and limited static value bindings. Directory builtins use root/source/list/binary context; project() seeds its actual directory rather than startup cwd. Cache/parent writes remain nonlocal facts.

## Explicit runtime layer

- `runtime_cmake/{model,process,trace}.rs`: typed run/event IDs, frame depth, asynchronous Configure (-S/-B) or Script (-P) execution with expanded JSON trace, cancellation/time/output bounds, and blocking decoding. JSON v1 minor 2 global_frame is required. Runtime settings use named defaults, positive limits, defining-file-relative paths, and validated arguments; script admission rejects configure-only flags. Script cwd is startup cwd, no build directory is used, and all observed script inputs participate in saved-input checks.
- `workspace/runtime.rs` and `runtime/model.rs`: independent immutable RuntimeLayer, source snapshots, execution-qualified values, function/macro declarations/calls, and dependencies. Source mapping is optional when files disappear or same-line commands are ambiguous. Layer assembly runs on a bounded worker; static graphs/snapshots are not rewritten. Runtime files join ownership and observed calls supplement unknown-command diagnostics.
- Expanded views retain repeated execution events and return bounded text plus structured data. Trace does not provide a complete variable store: only ordinary assignments, forced cache values, and unambiguous whole-quoted reads are observed; other reads/nonlocal values remain unknown. See [Runtime analysis](../src/runtime_cmake/README.md).

## Deliberate limits

The default pipeline is static structural/reference analysis; configure/script execution defaults to manual actions, with user/explicit-authorized on-save mode available. Static ordinary-variable references and possible function/macro calls are indexed; unknown/unset/empty ordinary-variable reads can produce warnings. General argument validation, arbitrary-position runtime variable inspection, static function/macro execution, complete runtime caller scopes, cache fallback, and `PARENT_SCOPE`/`PROPAGATE` evaluation are not implemented. A dedicated build directory is not a sandbox; authorized project code may spawn processes, access the network, or write elsewhere. Injected schemas may explicitly retain Unmodeled branches; final builtin override layers have no opaque keyword tails. Function-body writes are snapshot-local possible writes, not evidence of a function call.

The CmakeAnalyzer document-symbol handler consumes `SemanticedBuffer.symbols`, blocks, and command spans; semantic and build diagnostics feed push publications. Analyzer tests are wired through `tests/suite.rs` and `tests/integration.rs`. `tests/unit/parser/{semanticer,build_struct}.rs` cover scopes, templates, diagnostics, source-qualified facts, target kinds, and source file sets; `tests/unit/workspace.rs` covers overlays/revisions, repeated visits, missing candidates, cycles, and limits.

`crates/lspally/tests/suite.rs` loads RPC and duplex integration tests. The explicit 73-method fixture retains script provenance and marks manual test edits. Integration tests cover lifecycle, callbacks, ordering, cancellation, extension routing, EOF, blocked writes, and worker failure. Private conversion tests and performance checks are externally wired from `server/wrapper.rs` without widening adapter visibility. Ignored release-mode checks measure completion adapters, token encoding, and hover round trips; reproduction and timing limits are in `crates/lspally/tests/performance/README.md`.
