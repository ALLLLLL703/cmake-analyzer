# Analyzer LSP startup

```sh
cmake-analyzer --stdio
cmake-analyzer --root /path/to/project --root /path/to/another/project
cmake-analyzer --unix-socket /tmp/cmake-analyzer.sock
```

Stdio is the default. Unix sockets accept one client per process and use the same Content-Length framing, not raw newline-delimited JSON. The socket path must not already exist. Normal completion removes the bound path; forced process termination can leave it behind.

TOML settings merge user, project, and explicit `--config PATH.toml` files. Module search directories, feature switches, static interpreter commands, and manual/authorized on-save runtime settings are supported. See [Configuration](../config/README.md) for syntax and the process-wide `cmake-analyzer/reloadConfig` request.

## Reading order

- `src/cli/{args,transport}.rs`: clap arguments, stream creation, Wrapper startup, and worker cleanup.
- `roots.rs`: explicit root validation and nearest-ancestor CMakeLists.txt discovery. No recursive child scan.
- `model.rs`: CmakeAnalyzer, service state, and message/analysis models.
- `handlers.rs`: initialization, capabilities, and initial roots. CLI roots override initial client folders; otherwise workspaceFolders, rootUri/rootPath, then startup directory are used.
- `handlers/implementation.rs`: explicit ILanguageServer implementation generated by `scripts/gen/cmake_server.py`. Supported handlers forward to feature code; unadvertised handlers return Unsupported.
- `service/runtime.rs`: one bounded actor owns all Workspaces, batches ready edits, and treats hover/navigation/symbol/reload queries as ordering barriers.
- `hovers/`: builtin command/variable help and source-comment documentation alongside per-reference possible values; `hovers.rs` dispatches requests. See [hover documentation](hovers/README.md).
- `navigation/`: definition and references over qualified reference indexes; see [navigation](navigation/README.md).
- `paths/`: schema input-path candidates, asynchronous metadata checks, and cached warnings. Output/generated/unknown paths are excluded.
- `service/automatic.rs`: globally authorized on-save scheduling through the action entrypoints, coalesced per entry/profile.
- `configuration.rs`, `service/configuration.rs`: custom reload RPC and staged configuration/Workspace replacement.
- `action/`: dispatch plus one entry function per configure, expanded-argument, and cancellation action file.
- `service/configure.rs`: saved-input checks, tracked background jobs, invalidation, and runtime-layer installation.
- `service/projects.rs`: dependency-first ownership, shared overlays, root creation, and reassignment after dependency changes.
- `service/reports.rs`, `diagnostics.rs`, `symbols.rs`, `text.rs`: snapshot-to-LSP conversion.

## Workspace lifetime

Initialization selects initial projects and validates configuration; initialized starts the background service. An explicit interpreter mapping selects its project/script entry first. Otherwise, opening a file selects:

1. All existing projects whose dependency visits or search candidates contain the file.
2. The deepest existing project directory containing it.
3. A new project from its nearest ancestor CMakeLists.txt.
4. A standalone Workspace rooted at that file.

Project Workspaces refresh their dependency graphs. Standalone Workspaces only analyze local documents, without following include/subdirectory dependencies. An already-open external module is overlaid into newly discovered importing projects. Detached external modules are reassigned without losing unsaved text. Shared modules update every importing Workspace.

The service has a 64-message queue and a 64-edit batch policy, both named statics. Process-wide `[limits]` configures max_workspaces (default 32) and max_open_documents (default 256) through user/explicit configuration; project-local settings cannot change these caps. Reload rejects limits below current live counts. Existing per-Workspace parsing/traversal limits still apply. Shutdown cancels and joins the service. The CLI also calls `CmakeAnalyzer::stop()` after Wrapper returns, including EOF. Library callers retaining a CmakeAnalyzer clone should do the same.

## Diagnostics and symbols

- didOpen/didChange/didSave/didClose update overlays in notification order. Edits in one notification apply sequentially. Non-increasing versions and invalid encoded ranges are rejected without modifying stored text.
- Workspace uses the existing incremental lexer/parser/semantic/build pipeline. Queued edits supersede unpublished diagnostic batches; symbol queries observe preceding edits, not later queued edits.
- Push diagnostics combine semantic, build, and dependency errors for open documents. Variable warnings use Workspace invocation context for visited files (local warnings otherwise) and severity 2; external function bindings suppress local unknown-command errors. Snapshot-local reference/function records and immutable Workspace aggregates are described in [References](../parser/semanticer/REFERENCES.md). Failed child reads are warnings at the caller's include/subdirectory range; cycle/traversal failures remain errors. Diagnostic messages do not prepend or append file-origin labels; URI/range provide the location. Paths that are the subject of a check remain part of its message. Known input paths warn for missing or wrong-kind entries; outputs, known generated paths, expressions, unknown values, and unexecuted conditional/deferred inputs are excluded. See [path checks](paths/README.md). Closing a published document sends an empty report. Unopened project files are analyzed but do not receive diagnostic publications.
- Publication keys use version, weak snapshot identity, contextual warnings/resolved calls, and dependency diagnostics. Unchanged reports are not converted or sent again; obsolete snapshots are not retained by that cache.
- Positions use UTF-16 negotiation and byte-span conversion; the mapper also supports UTF-8/UTF-32. It indexes line starts and multibyte characters instead of rescanning line prefixes per symbol/diagnostic.
- Document symbols use SemanticedBuffer root symbols and direct block membership. Nested blocks assemble bottom-up; clients without hierarchical support receive SymbolInformation records. No builtin-variable catalogue dump or CMake execution is involved.

Interpreter commands select -S/-B project or -P script entries without executing during parsing. Configured scripts can subsequently run through their manual action. Default module paths include entry-relative cmake, cmake/Modules, and cmake/modules. Builtin modules are discovered once per configuration generation from PATH CMake's executable location and version for standard installation layouts; explicit configuration takes precedence. Detection never runs configure or project scripts. Pull diagnostics and filesystem watching are not implemented. Other LSP features remain unadvertised.

## Navigation

`textDocument/definition` and `textDocument/references` use existing variable,
function/macro, parameter, and used-builtin reference relations. Results include
cross-file targets, honor includeDeclaration, and deduplicate repeated physical
locations. Shared-file queries keep Workspace ID namespaces separate. Standalone
files reuse the reference collector. Builtin commands have references but no
source definition; unbound names do not receive guessed targets. Navigation observes
preceding edits and never executes CMake. See [details and limits](navigation/README.md).

## Variable hover

`textDocument/hover` supports variables and command/function/macro names. Variable
hover selects the name, not the whole argument, and shows the value at that
reference rather than the variable's last assignment. Builtin help is read on
demand through the startup PATH CMake's help flags and cached until successful
reload. Missing native help has no fallback. Exact/template names use the local
catalog, without fixed installation paths or a bundled manual. Adjacent
leading comments document function/macro declarations and set-derived variables,
including statically resolved cross-file definitions. See [binding rules](hovers/README.md). Static visits remain distinct for repeated
includes. Values use Static: and Observed: labels without visit/run/event details;
unknown is distinct from an empty string. Hover runs only native help inspection,
never a configure or project script. Project runtime.executable is not used for help.
The configured
runtime.max_view_bytes bounds values and documentation together. Markdown is used
when preferred by the client, otherwise plaintext. Runtime state is partial, not a
complete variable store.

## Manual Code Actions

1. Save related files.
2. Request Code Actions and select **Run CMake for … (executes project code)**.
3. Wait for the completion notification. A **Cancel CMake run** action is
   available while the child runs; ordinary requests/edits remain available.
4. Select **Show observed expanded arguments at this line** on an executed command, including a
   continuation line. Repeated executions retain separate event/frame records.

The commands are cmake-analyzer.configure, cmake-analyzer.runScript,
cmake-analyzer.expandedArguments, and cmake-analyzer.cancelConfigure (cancels
either mode). Actions supply four positional arguments:
`["file:///project/CMakeLists.txt", "/project/CMakeLists.txt", 3, "configure"]`.
The final profile is configure or script; legacy three-argument calls remain
accepted. Profiles distinguish script/configure Workspaces sharing an entry.
The line is zero-based. Project membership is validated. Automatic Code Action
requests return no actions; configuration alone never starts a run. User/explicit
configuration may authorize `runtime.mode = "on_save"`; a subsequent save then
uses the same configure/script action entrypoint. Default mode is action.
See [authorization and save behavior](../config/README.md#runtime-analysis).

Configure returns an immediate started/run acknowledgement. Expanded arguments
return run, events, and truncated fields and also show formatted text for
clients that discard executeCommand results. Events expose expanded arguments,
observed_values, and dependency targets. Unknown values are null. Per-event
IDs distinguish repeated source locations; frame depth alone is not a scope ID.

Source files must match saved text. Closed changed inputs are refreshed before
running. Known input changes during execution discard the result; unsaved newly
observed files also prevent installation. Changes/save/close/folder events and
successful configuration reload clear results and cancel runs. File events
invalidate affected entries; folder/reload changes invalidate all entries. There is no
filesystem watcher; inspection checks known saved inputs. Configure-generated
sources inside its build directory are not frozen as prior source inputs.

Configured -P mappings expose **Run CMake script for … (executes project code)**
instead of configure, regardless of filename. They use startup cwd without a
build directory. See [script configuration](../config/README.md#configured-script-execution).

Runtime documents join ownership; opening them exposes their parsed symbols.
Observed function/macro calls suppress matching unknown-command diagnostics.
Static snapshots, reference indexes, and other static warnings are not replaced.
Runtime source analysis/installation still uses the serialized Workspace phase.
This is expanded-command observation, not complete variable-state execution or
arbitrary-position inspection. See [runtime boundaries](../runtime_cmake/README.md)
and [runtime settings](../config/README.md#runtime-analysis).
